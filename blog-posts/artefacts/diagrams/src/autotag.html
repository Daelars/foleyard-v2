Foleyard v2 · auto tag

How a tag gets onto one of your files

Three routes in, three different levels of trust, and every one of them records who did it. That last part is the point: a tag you cannot trace is worse than no tag.

Trigger
A scan finishes
New files land in the index. If Auto Tag is switched on and approved, the app submits chunked, repeatable jobs. If it is off, nothing happens at all.
→
Route 1
Filename rules
Deterministic rules read the name and existing metadata. You can preview the plan before a single write happens.
→
Written as
D · rules
Stored with origin deterministic and a confidence value.
↓
Route 2
Candidate queue
Suggestions sit in a paged queue and write nothing while you browse them. Dismiss one and it stops coming back.
→
Gate
You press accept
Promoting a candidate is the only thing that turns it into a real tag.
→
Written as
M · manual
Your decision, recorded as yours. Manual tags win on read.
↓
Route 3
Semantic tagging
Opt-in. You consent to the model download, it runs against an approved vocabulary, and only tags that clear the confidence bar are considered.
→
Side effect
Vectors, kept
The embedding store keeps model-keyed vectors so "find similar" can rank neighbors by cosine distance.
→
Written as
AI · semantic
Stored with origin semantic_ai, and marked as such everywhere it appears.

Origins are visible, not internal

Every tag in a file row carries an M, D or AI mark, and the library has an origin filter across the top: All, Manual, Rules, AI.

You can undo the machine

Because the origin travels with the tag, you can revert in bulk by origin. Change your mind about the model and its work comes off without touching what you typed.

Moving a file keeps its history

Origins and vectors follow the file instead of being quietly dropped when it moves.

On the development branch, not in 0.1.8. Semantic tagging currently ranks stub vectors behind an explicit inference seam; the model side is not finished.

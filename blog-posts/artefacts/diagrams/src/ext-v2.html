Foleyard extensions · v2

How a tool runs in Foleyard v2

Same job, rebuilt from scratch rather than layered on top. A tool now declares what it is and what it needs before it is allowed to do anything, and long work runs as a job you can watch, cancel and recover.

Definition
Contract first
The tool declares its commands, settings, surfaces and permissions up front, as data.
→
Catalog
Serializable catalog
The host builds a sanitized description of every tool. The UI reads that, never the tool itself.
→
Registry
Only what the contract allows
Registration is rejected if the definition does not match the contract.
→
Availability
Can this run here, now?
One place answers it: enabled, approved, in scope, valid selection.
↓
Permissions
Declared, then approved
Nothing is implicit. An undeclared call throws, and the host reports permission-denied.
→
Filesystem
One adapter, enforced
All disk access goes through the seam. There is no node:fs fallback to take.
→
Jobs
Progress, cancel, recover
Work runs in chunks that report where they are and survive a restart.
→
Apply
Preview → review → apply
A tool can show you what it is about to do before it does it.

Switching off means something

Turning a tool off rejects new work, cancels live jobs, and removes its UI once the work it owns has settled. It is not a hidden checkbox.

Tools add UI without reaching in

Contribution adapters let a tool add a panel, a button or a page. The app never imports the tool, and the tool never imports the app.

Seven tools run on this today

Make Pack, Sound Shelf, Smart Collections, Folder Janitor, Library Gatherer, Drop Rules, and Auto Tag, which was built on v2 from the start.

Evidence: packages/yard-core/src/extensions-v2/, src/lib/extensions-v2/. Built on the 197-board development branch, not in 0.1.8.
